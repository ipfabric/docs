## Breaking Changes

### New Cloud Model Enabled by Default

The [New Cloud Model](../../System_Administration/Command_Line_Interface/Feature_Flags.md#new-cloud-model) is now enabled by default.

The New Cloud Model uses new database tables. Snapshots taken with the old model — before upgrading to `8.2` or with this feature flag disabled — are not compatible with the new model. Loading such a snapshot with the New Cloud Model may result in missing or incomplete data. The old snapshot data cannot be mapped to the new table structure.

To temporarily switch back to the old cloud model, see [Disabling the Feature Flag](../../System_Administration/Command_Line_Interface/Feature_Flags.md#disabling-the-feature-flag).

### Fast Discovery for Cisco Wireless LAN Controllers Enabled by Default

The `ENABLE_WLC_FAST_DISCOVERY` feature flag now defaults to `true`. IP Fabric discovers supported Cisco Wireless LAN Controllers using controller-wide (bulk) CLI commands.
Some per-access-point and per-client details are no longer collected by default.
To restore full discovery, see [Feature Flags](../../System_Administration/Command_Line_Interface/Feature_Flags.md#fast-discovery-for-cisco-wireless-lan-controllers).

### Application Infrastructure Mapping (AIM)

**Illumio Integration**

Each Illumio integration now has two switches: **Reject unauthorized certificates** and **Use system proxy configuration**. With certificate
validation turned off, IP Fabric can connect to an Illumio PCE whose TLS certificate is self-signed or issued by a CA the appliance does not trust,
both in **Test connection** and during discovery. Both switches are on by default, so existing integrations and snapshots behave as before.
See [Application Mapping](../../IP_Fabric_Settings/Discovery_and_Snapshots/Discovery_Settings/application_mapping.md#add-or-edit-an-integration-provider).

### Bug Fixes

#### AIM

Fixed `POST /aim/flow-path-lookups/{snapshotId}` rejecting the `$last`, `$lastLocked`, and `$prev` snapshot keywords. They are now resolved, as in `POST /aim/import/{snapshotId}`.

## v8.2.1 (October 26th, 2026; Preview)

### Improvements

#### Path Lookup

Path Lookup now follows paths across the boundary between an **Extreme SPBM fabric and a standard Ethernet network**
where no STP runs between them. IP Fabric **uses LLDP to link a Switched UNI (S-UNI) port** with a configured I-SID
to the neighboring Ethernet switch port, for VLANs that match on both sides. This works on physical ports
and MLT aggregates. LLDP must be enabled on the S-UNI ports. See [Fabric Edge Without STP](../../IP_Fabric_GUI/technology_tables/spbm.md#fabric-edge-without-stp) for details.

#### Vendor Support

**GCP**

**Operating System and Image** -- IP Fabric now collects the operating system
type and image of GCP virtual machines. It resolves both from the
boot disk of the virtual machine and its source image. These fields were previously
empty for GCP.

!!! warning "New GCP Permissions Required"

    Add the `compute.disks.list` and `compute.images.get` permissions
    to your [GCP IAM role](../../IP_Fabric_Settings/Discovery_and_Snapshots/Discovery_Settings/Vendors_API/GCP_Google_Cloud_Platform.md#how-to-create-a-custom-role) to enable this feature.

**Disabled APIs Are No Longer Queried** -- IP Fabric now uses the Service Usage API to detect which APIs are enabled in each project and skips requests to disabled ones, preventing `SERVICE_DISABLED` errors in discovery and in GCP audit logs. To benefit from this, enable the Service Usage API in the service account's project and add the `serviceusage.services.list` permission to the IP Fabric role. Without it, discovery works as before. See [Google Cloud Platform (GCP)](../../IP_Fabric_Settings/Discovery_and_Snapshots/Discovery_Settings/Vendors_API/GCP_Google_Cloud_Platform.md).

**Avocent ACS**

IP Fabric now supports foundation discovery of Avocent ACS console servers over SSH.
Coverage includes :

- basic device inventory — hostname, serial number, model, OS version, and memory,
- configuration snapshot management services including DNS, NTP, and syslog.

See [Feature Matrix](https://matrix.ipfabric.io/) for details.

!!! warning "Disabled by Default"
    To enable it, set the `ENABLE_DISCOVERY_DEVICES_AVOCENT` feature flag. See [Feature Flags](../../System_Administration/Command_Line_Interface/Feature_Flags.md#avocent-acs-discovery) for details.

#### MCP Server

- Raised the MCP server's request body limit for JSON payloads from 100 KB to 20 MB, matching the IP Fabric API, so larger AIM imports through
  `POST /aim/import/{snapshotId}` are no longer rejected by the MCP server.

### Experimental Features

#### Aruba Central Discovery (Partial)

IP Fabric can now partially discover devices managed by HPE Aruba Networking Central via API.

Disabled by default. To enable it, see [Feature Flags](../../System_Administration/Command_Line_Interface/Feature_Flags.md#aruba-central-discovery-partial).

#### Avocent ACS Discovery

Avocent ACS Discovery is disabled by default. To enable it, see [Feature Flags](../../System_Administration/Command_Line_Interface/Feature_Flags.md#avocent-acs-discovery).

#### Reserved Labels

Label names starting with `ipf_` are now reserved. IP Fabric publishes the site,
routing domain, and STP domain it calculates for each device as the
`ipf_site`, `ipf_routingDomain`, and `ipf_stpDomain` labels. You can override
them manually or with rules. Tables and diagrams use the overridden values.
The new `ipf_region` label groups devices into regions, and diagrams can now be
grouped by **Region**. See [Reserved Labels](../../IP_Fabric_Settings/Discovery_Data_Enrichment/reserved_labels.md)
for details.

Disabled by default. To enable it, see [Feature Flags](../../System_Administration/Command_Line_Interface/Feature_Flags.md#labels).

#### Label-Based Access Control

Roles can now be restricted to the devices and interfaces carrying specific
labels. Enrol labels for RBAC, combine them into data policies in the new
**Settings --> Administration --> Data policies** page, and link data policies
to roles together with endpoint policies, which define the API endpoints a role
may call. See [Label-Based Access Control](../../IP_Fabric_Settings/administration/label_based_access_control.md)
for details.

Disabled by default. To enable it, see [Feature Flags](../../System_Administration/Command_Line_Interface/Feature_Flags.md#labels).

#### Fast Discovery for Cisco Wireless LAN Controllers Enabled by Default

The `ENABLE_WLC_FAST_DISCOVERY` feature flag now defaults to `true`. IP Fabric discovers supported Cisco Wireless LAN Controllers using controller-wide (bulk) CLI commands. Some per-access-point and per-client details are no longer collected by default. To restore full discovery, see [Feature Flags](../../System_Administration/Command_Line_Interface/Feature_Flags.md#fast-discovery-for-cisco-wireless-lan-controllers).
